API Documentation

Overview

The Darija ASR API provides programmatic access to our speech-to-text transcription service, supporting Moroccan Arabic (Darija), Standard Arabic, and French languages.

Base URL
{{ request.url_root }}api/v1
Supported Formats
  • Audio: MP3, WAV, M4A, OGG, FLAC
  • Max file size: 16MB
  • Response: JSON

Authentication

All API requests require authentication using an API token.

Include your API token in the request header:

X-API-Token: YOUR_API_TOKEN
Getting an API Token
  1. Login to your dashboard
  2. Navigate to API Tokens
  3. Click "Create New Token"
  4. Save your token securely (you won't be able to see it again)

Rate Limits

Default Limits
  • 100 requests per hour per token
  • 16MB maximum file size
  • 60 seconds request timeout

Rate limit information is included in response headers:

X-RateLimit-Limit: 100 X-RateLimit-Remaining: 95 X-RateLimit-Reset: 1640995200

API Endpoints

POST /api/v1/transcribe

Transcribe an audio file to text.

Request Parameters
Parameter Type Required Description
audio file Required Audio file to transcribe (MP3, WAV, M4A, OGG, FLAC)
language string Optional Target language: ar-MA (default), ar, fr-FR
Headers
Header Value Required
X-API-Token Your API token Required
Content-Type multipart/form-data Required
Response
200 OK - Successful transcription 
{
    "success": true,
    "transcription": "شوف لي الصنداله شحال باقي فيه",
    "id": 123,
    "language": "ar-MA",
    "confidence": 0.95
}
400 Bad Request - Invalid request 
{
    "error": "No audio file uploaded"
}
401 Unauthorized - Invalid or missing token 
{
    "error": "Invalid token"
}

Error Handling

The API uses standard HTTP status codes to indicate success or failure.

Status Code Description
200 Success - Request completed successfully
400 Bad Request - Invalid parameters or missing required fields
401 Unauthorized - Invalid or missing API token
413 Payload Too Large - File size exceeds 16MB limit
429 Too Many Requests - Rate limit exceeded
500 Internal Server Error - Something went wrong on our end
Error Response Format
{
    "error": "Descriptive error message",
    "code": "ERROR_CODE",
    "details": {
        // Additional error details if available
    }
}

Best Practices

Recommendations
  • Audio Quality: Use high-quality audio (16kHz or higher) for best results
  • File Format: WAV format provides the best compatibility and speed
  • Error Handling: Always implement retry logic with exponential backoff
  • Token Security: Never expose your API token in client-side code
  • Rate Limiting: Implement client-side rate limiting to avoid hitting limits
  • Batch Processing: For multiple files, process them sequentially to avoid overwhelming the API
Security
  • Always use HTTPS in production
  • Store API tokens in environment variables, not in code
  • Rotate tokens regularly
  • Monitor token usage for unusual activity
Language Tips
  • Moroccan Darija (ar-MA): Best for Moroccan dialect speech
  • Standard Arabic (ar): Use for formal Arabic speech
  • French (fr-FR): Good for French or mixed French-Darija content
  • The API automatically handles code-switching between languages
